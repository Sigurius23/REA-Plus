# Repository completeness review — draft for review

**Review date:** 2026-10-11  
**Source of truth:** `game-modding-research-index/resources.json` (384 records; last reviewed 2026-10-11), checked against `platforms/android-steam-tool-map.html` and `ECOSYSTEM_COVERAGE.md`.

## Scope and how to read “most complete”

This ranks **the repositories already in the catalog** for the workstreams asked about: Android app/game analysis, Steam PC game analysis, mod/data merging, Rust rewrites, and binary analysis. It is not a row for every unrelated item among the 384 records. Relevant alternative repositories and the catalog’s adjacent references are included below so a “best” pick is not mistaken for a universal solution.

- **No single repository is complete across all of these jobs.** “Most complete” means broadest within a named tool role and target—not universal title/build support or independent compatibility testing.
- **Steam is a store/distribution platform, not an engine.** Choose based on executable, runtime, asset format, and exact game build/store edition.
- **Merging** below means merging game mods, patches, or structured game data. If “merging” meant Git/source-branch merging, the current game-modding catalog has no general Git merge assistant.
- Keep the role distinctions: a **loader/framework** runs mods; an **asset/archive tool** reads or edits files; a **manager** installs/orders packages; a **reference/index** points to material; a **binary-analysis tool** inspects executable code. These are not substitutes.
- The HTML map’s header says “382 resources · 8 Oct 2026.” The current `ECOSYSTEM_COVERAGE.md` and JSON explain the later 384 count: **ELDEN RING Combat Rewrite** and **Faith Runner** were added on 2026-10-11. I use the current JSON count; the engine matrix remains a finite catalog audit, not universal coverage.

**Best practical Android stack by role:** APK Analyzer + ADB for inventory/device evidence; JADX for code; Apktool for resources/Smali; MobSF for automated triage; Ghidra for native libraries; Frida/Objection for runtime analysis; REA as an agent-facing bridge where its provider requirements match. None alone is “the complete reverse engineer.”

## Recommendation

For a practical stack, select one tool per layer rather than trying to install every catalog entry:

1. **Android:** MobSF for broad automated triage; JADX + Apktool for code/resources; Ghidra for native libraries; ADB/Logcat plus Frida/Objection for runtime evidence; REA if its current provider requirements fit the work.
2. **Steam PC:** identify the exact game/build, engine, runtime, and artifact first. Use REA/Ghidra for code, then the corresponding engine-specific asset tool in the matrix. Do not use a loader or mod manager as a substitute for an analyzer.
3. **Merging:** choose G3M, RPGModder, MV Mod Loader, or ModuleManager only for the target and merge semantics each documents. There is no cross-engine merger in the list.
4. **Rust rewrite study:** start with benilla for a full client architecture; compare Gang Beasts Rust for a playable local game engine and IW4L for a networked FPS runtime. Treat Elden Ring Combat Rewrite and Faith Runner as subsystem studies.
5. **Binary analysis:** Ghidra is the default broad native workbench; REA is the agent-facing layer. Add a runtime debugger, managed/DEX decompiler, or format parser only when the artifact requires it.

This is a catalog-based comparison, not a compatibility test. No tools were installed and no existing catalog/map files were edited.
