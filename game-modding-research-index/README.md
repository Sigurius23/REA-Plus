# Game Modding & Reverse-Engineering Index

A curated, link-only meta-repository for AI-assisted game modding, coding-agent workflows, engine-specific mod frameworks, reverse engineering, decompilation, asset tools, and console research.

> **This is an index, not a monorepo.** It links to original projects and public documentation.

> **Scope note:** The broader reverse-engineering list includes specialist malware/forensics, network/protocol, and firmware/hardware tools, categorized separately from game-modding frameworks and loaders.

### Runtime modding frameworks and explorers

- **[BepInEx](https://github.com/BepInEx/BepInEx)** — Unity/XNA patcher and plugin framework. Stable v5 is in LTS (latest checked 5.4.23.5, 2026-02-08) and is the recommended line for Mono games; Unity IL2CPP uses separate v6 bleeding-edge builds (latest checked 6.0.0-be.788, 2026-09-01). Match backend, platform, architecture, and game build; bleeding-edge builds may contain bugs.
- **[MonoMod](https://github.com/MonoMod/MonoMod)** — Actively developed .NET modding basework with IL patching and runtime detours/hooks; useful to compatible Mono/.NET/XNA/FNA games, but not a plug-and-play loader for every game.
- **[Ultimate ASI Loader](https://github.com/ThirteenAG/Ultimate-ASI-Loader)** — Cross-game proxy-DLL layer for ASI plugins, with Win32/Win64 variants; v9.7.4 was released 2026-08-16. ## Suggested starting points

- Pick an AI coding agent/harness and give it access only to the project files it needs. The AI Game Modding Guides repo says MCP is optional to start.
- For a game mod, first identify the engine, exact game version, and an existing supported loader/API; choose one loader rather than mixing alternatives blindly. The linked guide says its passthrough examples target Windows and treats Wine/Proton as unverified; Rust rewrites are a different path, though the player's game data still has to be readable on that OS.
- Mod managers are optional installation/deployment helpers, not development prerequisites.
- For static binary analysis, compare **REA**, **Ghidra**, and the available **MCP** bridges. **Frida** covers runtime instrumentation rather than static decompilation.
- For Unreal Engine, distinguish **UE4SS** (a game-specific runtime scripting/mod framework), **FModel** (archive/asset inspection), and title-specific authoring tools such as the Hogwarts Creator Kit or ARK DevKit. Match the exact game build, engine version, store, and mod format; a UE4/UE5 label or archive-parser support does not prove loader compatibility.
- For GameMaker, separate **UndertaleModTool** (data-file/GML VM editor), **YYToolkit** (runtime framework with a narrow version/platform matrix), and **G3M**/**Deltamod** (mod managers/patch drivers, not runtime loaders; G3M also provides discovery/profiles). Compatibility varies by VM versus YYC, title/data file/store, and mod package target; a `data.win` patch or a GameMaker engine label alone does not establish compatibility.
- For Source games, keep branches and title toolchains separate: HL2 20th Anniversary Workshop and Source SDK 2013 SP are not identical; Portal 2 has its own Steam authoring suite (no native Linux support; Proton is caveated); Alyx has its own Source 2 Workshop Tools. Portal 2: Community Edition is a distinct Strata Source open beta, not a Source 2 port or a vanilla-game mod installer.
- For Ren'Py/visual novels, distinguish engine authoring and translation from title-specific templates, managers, archive tools, and decompilers. For DDLC, the original PC game is Ren'Py; Plus is Unity, and the official mobile app is a separate release. The original PC game is Ren'Py; Plus uses Unity, and the official mobile app is a separate release with no established PC-tool compatibility.
- For Unity, identify the installed build's scripting backend before selecting a loader: Mono and IL2CPP need different binaries. `Managed` versus `il2cpp_data` are useful BepInEx clues, not universal proof; **AssetRipper** and **UABEA** handle different asset workflows, while **ILSpy**, **Cpp2IL**, and **Il2CppDumper** are analysis tools, not loaders.
- **AnyPS5** and **PortPS5** focus on porting PS5 executables to PC; **KytyPS5** and **SharpEmu** are experimental emulators for running PS5 software on PC. The PS5 homebrew emulator ports above run other systems on PS5; neither direction is a PS5 game-modding workflow.
