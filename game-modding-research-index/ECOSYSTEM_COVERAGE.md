This finite checklist is the audit target for major engine, title-family, platform, and distribution buckets proposed for the index. Its acceptance bar records each bucket as supported by an independently checked resource, Partial with the remaining limitation named, or Out of scope with a reason. The declared finite checklist meets that bar: no bucket remains Open. The checklist does **not** claim to represent every game ever released or establish every possible tool.

Coverage describes the index's research/discovery paths—not universal compatibility. Compatibility statements are specific to the game build, store edition, platform, mod, and tool version. Discovery indexes (including the Game Decompilations Index and UE Modding Tools Databank) provide leads; their linked entries are not independently validated by the index.

The reverse-engineering starter-stack expansion also catalogs specialist malware/forensics, network/protocol, and firmware/hardware references. These are not general game-modding tools and do not close any game/engine checklist row.

## Status meanings

- **Open** — the evaluation is incomplete. Candidate resources may already be catalogued, but they do not close the bucket; the table names the remaining checks.
- **Partial** — a bounded workflow or subset has been checked, but a material title branch, platform, or compatibility boundary remains unresolved; the table names it.
- **Covered** — the bucket's stated, limited scope has been checked against canonical project or official sources. This is not universal game coverage or a guarantee of current compatibility.
- **Out of scope** — no general workflow is mapped for this bucket; the reason and any related resources are stated. This is not a claim that no tool exists.

“Active”, “WIP”, “archived”, “legacy”, “experimental”, and “maintenance-sensitive” are resource-level maturity labels, not coverage statuses. A partial or archived resource’s maturity label alone does not identify a current support path.

### Mono and IL2CPP are separate Unity workflows

- Unity's [scripting-backend manual](https://docs.unity3d.com/6000.2/Documentation/Manual/scripting-backends-intro.html) describes Mono as JIT and IL2CPP as AOT; backend selection depends on the build target. An engine label alone cannot establish the backend of a shipped game.
- For Mono, BepInEx stable v5.4.23.5 is in LTS and the upstream release notes designate v5 for new Mono games. For IL2CPP, BepInEx distributes separate `Unity.IL2CPP` v6 bleeding-edge builds; the latest build inspected was 6.0.0-be.788 (2026-09-01), in the bleeding-edge channel. [MelonLoader](https://github.com/LavaGang/MelonLoader) v0.7.3 supports both backends, but support remains title/build-specific.
- The [BepInEx install guide](https://docs.bepinex.dev/master/articles/user_guide/installation/index.html) uses `Managed` and `il2cpp_data` as common folder clues and directs users to separate runtime/architecture binaries. The guide's `master` docs identify themselves as unreleased; release channel and executable architecture define the matching binary.
- The five named PC routes above are Mono/managed-plugin-oriented; no IL2CPP-specific route was confirmed for this candidate set. This is not a binary inspection of every store/platform edition. Tools such as Cpp2IL and Il2CppDumper are analysis/reconstruction tools, not IL2CPP loaders.

### GameMaker tool roles and upstream status

- **UndertaleModTool (UMT)** — active file editor/decompiler and scriptable patch authoring tool, not a runtime loader. Stable v0.9.2.0 (2026-08-23) updates some GameMaker 2026.1 beta file-format/code-generation handling and fixes observed in a Deltarune Chapter 5 test room. The Windows x64 GUI and cross-platform CLI are different delivery surfaces; code editing is for GML VM builds, not YYC code. Validate the exact `data.win`/`data.unx`/other input before saving.
- **YYToolkit** — actual runtime plugin/mod framework for Windows 8.1–11. Its README separates Legacy and Next support: Legacy lists GM 1.4.x/2.x/2022.x with some unreliable/limited areas; Next lists GM 2.x through 2024.x beta, with different VM/x86/x64 support. Stable v4.0.1 dates to 2025-03-13; the latest listed v5.0.0c (2026-03-03) is explicitly an unstable test beta that breaks v4 plugins. Its table does not declare support for newer GM 2026 or GMRT, and does not certify Undertale/Deltarune individually.
- **G3M and Deltamod** — managers/patch drivers, not runtime loaders. G3M v3.4.1 (2026-10-04) combines GameBanana browsing/discovery, profiles, launching, patching, merging, and data conversion; its built-in list includes Undertale and Deltarune. Deltamod v2.1.4 (2026-10-04) is a separate community packaged-mod manager; its release notes include Linux patch-tool and backup fixes. Manager OS downloads describe manager availability; game-build, store, and mod-package compatibility are separate.
- **YoYo Games' GMEXT-mod.io** — official developer extension for integrating mod.io UGC into a game project, not a general runtime mod loader. Its latest tagged release located is v1.0.2 (2024-12-18), associated with GameMaker LTS 2022; the main branch is marked work in progress. Current LTS 2026 compatibility is unverified.

### Tool roles and community discovery

- **Authoring:** the Ren'Py SDK and official developer tools support game creation/debugging. They are distinct from packaged-game mod managers.
- **Translation:** the official workflow targets creator-supplied scripts/templates; the docs say unsanctioned support is more limited.
- **DDLC template:** v5.1.0 is a community template for the original desktop game, with distinct Py3/Ren'Py 8 and Py2/Ren'Py 7 packages. It is not official and does not target Plus.
- **Manager:** DokiModManager installs/organizes DDLC mods; it is not itself a runtime loader. Its non-Windows builds and mod compatibility have explicit caveats.
- **Compiled-script decompiler:** `unrpyc` v2.0.4 (2026-02-24) decompiles `.rpyc` scripts but does not extract `.rpa`; v2.x uses Python 3.9+ and supports Ren'Py 8 down to 6.18.0 by CLI (older builds may require an option), while legacy v1.x targets Ren'Py 6/7. Upstream does not claim every version is actively tested.
- **Archive/decompile utility:** `rpa-toolkit` reads/writes RPA v1/v2/v3/v3.2 archives and handles RPYC/RPYMC decompilation, but is a small early-stage project with no GitHub releases/tags and only three commits visible at review. It is not a runtime loader; .
- **Discovery/reference:** the r/DDLCMods wiki is a community index, not official support. Some guidance is older and explicitly excludes later templates; current release pages provide the most recent version-selection information.

### Policy and unresolved boundaries

Team Salvato's current IP Guidelines document DDLC asset, fangame, distribution, character-depiction, and generative-AI topics. The community template's Android build option is separate from the official mobile app.

**Role and platform boundary:** me3 is the runtime framework/profile launcher and its [official docs](https://me3.help/en/latest/) list Windows, Linux/Steam Deck through Proton, and macOS through CrossOver; this is not a blanket title/mod matrix. Smithbox 2.2.6 (2026-09-20; main-branch activity through 2026-10-01) contains editors for the named games and states that its editors do not require game unpacking; its HKS/parameter support is feature- and version-specific. Nuxe [v1.2.1](https://github.com/JKAnderson/Nuxe/releases/tag/v1.2.1) (2026-08-27) is a data unpacker and optional executable patcher, not a mod manager or runtime; it is the upstream-designated successor to [UXM](https://github.com/JKAnderson/UXM) (archived 2026-09-02), and its open DS3 DLC issue reports an infinite loading screen after unpacking/patching. Mod Engine 2 was archived on 2024-07-19 and is a legacy option; old configs/mods are not interchangeable with me3.

Capcom RE Engine and FromSoftware therefore remain **Partial** in both the detailed checklist and the practical crosswalk. The named titles now have bounded upstream paths, official game-version references where found, and role-separated discovery/editor/asset/runtime tools. Still unresolved are exact current executable/store/build compatibility for RE2/3/4 and MHRise; the precise me3/Smithbox/Nuxe compatibility of each DS3/Sekiro/Elden Ring build and mod; the RT/non-RT branch mapping as game binaries change; and the DS3 Nuxe issue. No end-to-end install/mod test was run.
